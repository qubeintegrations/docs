## Responses

Every QuickBooks operation answers **`201 Created` with a queued request**, not with QuickBooks' data.
QuickBooks Desktop is only reachable when its Web Connector checks in, so the data arrives later, at your
`webhook_url`. Each operation's page documents that webhook as the operation's callback. See
[How it works](/how-it-works#why-every-request-is-asynchronous).

| Status | Means |
| --- | --- |
| `200`, `201` | Done, or queued. |
| `400` | The request was invalid and nothing was queued. `errors` says why. |
| `401` | Missing or wrong API key. |
| `404` | No such connection, request or workflow in this app. |
| `409` | A conflict, such as discarding a request the Web Connector already has. |
| `422` | Well-formed but refused, such as a workflow input that doesn't match its declared inputs. |

A QuickBooks refusal, such as a duplicate name, is not an HTTP error: the request was queued fine, and its
answer arrives by webhook with `state: "error"`. See [Error handling](/error_handling).

## For code generators and AI agents

- The OpenAPI 3.1 document is at [`https://qubesync.com/api/v2/openapi.json`](https://qubesync.com/api/v2/openapi.json).
  Point a client generator at it, or give it to your assistant.

  codes, without needing your API key.
