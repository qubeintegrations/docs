Answers from QuickBooks arrive as a `POST` to the `webhook_url` you pass with each request, so QuBe Sync has
to be able to reach it. On your laptop, a tunnel gives your local server a public HTTPS address.

<CodeGroup>
```bash Cloudflare Tunnel
# https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/
cloudflared tunnel --url http://localhost:3000   # your app's port
```

```bash ngrok
# https://ngrok.com
ngrok http 3000   # your app's port
```
</CodeGroup>

Both print a public URL. Use it as the base of your `webhook_url`:

<Request
  path="/api/v2/connections/{connection_id}/customers"
  query={{
    max_returned: 5,
    webhook_url: "https://abc123.trycloudflare.com/webhooks/qube",
  }}
/>

```http
GET /api/v2/connections/{connection_id}/customers?max_returned=5&webhook_url=https://abc123.trycloudflare.com/webhooks/qube
```

```bash
curl -u "$QUBE_API_KEY:" \
  -G \
  "https://qubesync.com/api/v2/connections/$CONN_ID/customers" \
  --data-urlencode "max_returned=5" \
  --data-urlencode "webhook_url=https://abc123.trycloudflare.com/webhooks/qube"
```

Tips:
- **Set up a permanent tunnel** using [Cloudflare Tunnels](https://developers.cloudflare.com/tunnel/get-started/)
- **Keep the URL in configuration** (an `APP_HOST` environment variable, say) and build every `webhook_url`
  from it, because a free tunnel's address changes each time it starts.
- **Verify signatures in development too.** Your sandbox app has its own webhook secret, so the code path is
  the same as in production. [Verify the signature](/webhooks#securing-your-endpoints).
- **Missed one while the tunnel was down?** QuBe Sync retries each delivery several times, and any request's
  page in the dashboard has **Resend webhook**.
